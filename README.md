# BLACKOUT 주문관리 앱

업체(시공업체) · BLACKOUT 관리자 · 제조공장이 하나의 시스템에서 주문을 처리하는 전용 주문관리 앱입니다.
휴대폰에 설치할 수 있는 **모바일 웹앱(PWA)** 방식이며, 외부 패키지 없이 Node.js 22 내장 SQLite로 동작합니다.

이 저장소는 기획안의 **1차 범위**를 구현합니다.

| 단계 | 범위 | 상태 |
|---|---|---|
| 1차 | 업체 주문 · 자동 견적 · 관리자 화면 · 공장 주문관리 · 송장 등록 · 변경 이력 | 구현 완료 |
| 2차 | 네이버 스마트스토어 주문 자동 수집 · 발주확인 · 송장 연동 · 취소 요청 처리 | 구현 완료 (API 키 입력 시 동작, 모의 모드 제공) |
| 3차 | 자동 결제 · 정산 · 알림 · 고급 분석 | 미구현 |

## 실행

요구 사항: Node.js 22.5 이상 (내장 `node:sqlite` 사용).

```bash
npm install          # bcryptjs 1개 (네이버 API 전자서명용)
npm start            # http://localhost:3000
npm run dev          # 파일 변경 시 자동 재시작
npm test             # 견적 계산 · API 권한 · 주문 흐름 테스트
```

최초 실행 시 `data/blackout.db`가 생성되고 아래 계정이 자동 등록됩니다. **운영 전 반드시 비밀번호를 변경하세요.**

| 역할 | 아이디 | 초기 비밀번호 | 비고 |
|---|---|---|---|
| 관리자 | `admin` | `admin1234` | 환경변수 `ADMIN_PASSWORD`로 변경 가능 |
| 공장 | `factory` | `factory1234` | 환경변수 `FACTORY_PASSWORD`로 변경 가능 |
| 업체(데모) | `vendor` | `vendor1234` | `SEED_DEMO=0`이면 생성하지 않음 |

환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서비스 포트 |
| `HOST` | `0.0.0.0` | 바인딩 주소 |
| `DB_PATH` | `data/blackout.db` | SQLite 파일 경로 |
| `SECURE_COOKIES` | 미설정 | HTTPS 뒤에서 운영 시 `1` (세션 쿠키 Secure 플래그) |
| `NAVER_CLIENT_ID` | 미설정 | 커머스API 애플리케이션 클라이언트 ID (설정 시 실서버 연동) |
| `NAVER_CLIENT_SECRET` | 미설정 | 커머스API 클라이언트 시크릿 |
| `SMARTSTORE_MODE` | 자동 | `live` / `mock` / `off`. 미설정 시 키가 있으면 live, 없으면 off |
| `SMARTSTORE_POLL_MINUTES` | `5` | 신규 주문·취소 요청 수집 주기(분) |

운영 서버 설치는 [deploy/README.md](deploy/README.md)를 보세요. Ubuntu 서버에서 명령 한 줄로 Node 설치 · 자동 시작 · HTTPS · 일일 백업까지 설정됩니다. PWA 설치(홈 화면 추가)는 HTTPS에서만 동작합니다.

## 휴대폰 설치 (PWA)

1. 휴대폰 브라우저(iOS Safari / Android Chrome)로 서비스 주소에 접속합니다.
2. iOS: 공유 → "홈 화면에 추가". Android: 메뉴 → "앱 설치" 또는 "홈 화면에 추가".
3. 홈 화면 아이콘으로 실행하면 전체 화면 앱처럼 동작합니다.

## 역할별 기능

### 업체 (vendor)
- 제품 형태(편개형/양개형/프리형), 가로×세로(mm), 프레임 색상, 허니콤 원단, 수량 입력
- 입력 즉시 **자동 견적** (최소 주문면적 · 업체별 단가 · 유형별 추가금 · 택배비 자동 적용)
- 배송지 · 수령인 · 설치 요청사항 입력 후 주문
- 접수/보류 상태에서는 주문 내용 수정 · 취소 가능 (수정 시 금액 자동 재계산, 이력 기록)
- 주문 진행 상태 · 택배사 · 송장번호 조회

### 관리자 (admin)
- 전체 주문 조회 (상태 · 업체 · 검색)
- 결제 확인 후 **발주 승인** → 공장에 자동 전달 / 보류 / 취소
- 업체 관리: 업체별 납품단가, 거래 중지
- 계정 관리: 업체 · 공장 · 관리자 계정 생성, 비밀번호 재설정, 사용 중지
- 가격 설정: 기본 단가, 최소 주문면적, 택배비, 제작원가, 제작 치수 범위, 제품 형태별 추가금
- 매출 · 마진 대시보드 (기간 · 월별 · 업체별), 관리자 메모(공장 · 업체 비노출)

### 공장 (factory)
- 승인된 **제작 주문서**만 확인 (제작 규격 · 배송지 · 설치 요청)
- 제작 시작 → 제작 완료 · 송장 등록(출고) → 송장 정정
- 주문서 인쇄 (브라우저 인쇄)
- **판매가 · 단가 · 마진 · 업체명 · 업체 목록 · 관리자 메모는 API 응답 자체에서 제거**되어 노출되지 않습니다.

## 주문 진행 단계

```
주문 접수(received) ─▶ 발주 승인(approved) ─▶ 제작 중(in_production) ─▶ 출고(shipped) ─▶ 배송 완료(delivered)
      │  ▲                    │
      ▼  │                    ▼
   보류(on_hold)           취소(cancelled)
```

| 전환 | 가능 계정 |
|---|---|
| 접수 → 승인 / 보류 / 취소 | 관리자 |
| 접수 · 보류 → 취소 | 업체, 관리자 |
| 승인 → 제작 중 | 공장 |
| 제작 중 → 출고 (송장 필수) | 공장 |
| 출고 → 배송 완료 | 업체, 관리자 |
| 승인 → 보류 / 취소 (제작 전 회수) | 관리자 |

규격 · 옵션 검증은 주문 생성 시 서버에서 수행되며, 통과하지 못한 주문은 생성되지 않습니다. 모든 생성 · 수정 · 상태 변경 · 송장 변경은 `order_history`에 기록됩니다.

## 가격 계산

```
실제 면적      = 가로(mm) × 세로(mm) / 1,000,000
과금 면적      = max(실제 면적, 최소 주문면적)        # 기본 2㎡
제품금액       = 과금 면적 × 단가 × 수량            # 단가: 업체별 단가 > 기본 단가(90,000원/㎡)
유형 추가금    = 제품 형태별 추가금 × 수량
최종 주문금액  = 제품금액 + 유형 추가금 + 택배비      # 택배비 기본 8,800원 (업체 부담, 1회)
마진(관리자)   = 제품금액 + 유형 추가금 − 제작원가
```

예시: 편개형 1,000×2,000mm (2㎡) → 180,000 + 8,800 = **188,800원**

기본값은 단가 90,000원/㎡, 양개형·프리형 추가금 각 50,000원입니다. 제작원가 60,000원/㎡는 마진 계산용 예시 값이므로 관리자 "가격설정" 화면에서 실제 값으로 변경하세요. 설정 변경은 이후 주문부터 적용되고, 기존 주문 금액은 주문 시점 값으로 보존됩니다.

## 네이버 스마트스토어 연동

### 동작 방식

네이버는 주문을 서버로 밀어주지 않으므로 앱이 주기적으로 커머스 API를 호출합니다.

| 시점 | 동작 |
|---|---|
| 주기 수집 (기본 5분) | 결제완료(PAYED) 상품주문 조회 → 구매 옵션·배송 메모를 제작 규격으로 변환 → 규격 검증 통과 시 "접수" 주문 자동 생성, 실패 시 "확인 필요" 목록에 보관 |
| 주기 수집 | 구매자 취소 요청 조회 → 제작 전이면 주문을 자동 보류, 제작 중이면 이력에 경고 기록 |
| 관리자 승인 | 네이버 **발주확인** API 호출 후 승인 (실패하면 승인되지 않음) |
| 공장 송장 등록 | 네이버 **발송처리** API 호출 (택배사 코드 자동 변환). 실패해도 출고는 유지되고 다음 수집 때 재전송 |
| 관리자 취소 승인 | 네이버 취소 승인 API 호출 + 내부 주문 취소 |

스마트스토어 주문은 업체 단가가 아닌 **네이버 결제 금액**이 매출로 잡히며, 매출·마진 화면에서 업체 주문과 분리되어 표시됩니다. 공장 화면은 업체 주문과 동일하게 규격·배송지만 보입니다.

### 실서버 연결 절차

1. 스마트스토어 판매자 계정으로 [커머스API센터](https://apicenter.commerce.naver.com)에서 API 이용을 신청합니다 (사업자 판매자, 승인까지 수일).
2. 승인 후 애플리케이션을 등록합니다. 유형은 **판매자 본인 스토어용**, 권한은 주문 조회 · 발주/발송 처리 · 클레임 조회. 앱을 운영할 서버의 **고정 IP**를 호출 IP로 등록해야 합니다.
3. 발급된 클라이언트 ID/시크릿을 서버 환경변수 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에 넣고 재시작합니다. 채팅·문서에 값을 복사하지 마세요.
4. 관리자 → 스마트스토어 탭에서 "지금 동기화"를 눌러 연결을 확인합니다. 오류는 동기화 기록에 표시됩니다.
5. 상품 옵션을 기계가 읽을 수 있게 구성합니다. 권장 형식은 `제품형태: 양개형 / 프레임: 블랙 / 원단: 그레이 / 가로(mm): 1200 / 세로(mm): 1800` 입니다. 치수는 직접 입력형 옵션으로 받고, `가로 120cm`처럼 cm 단위나 `1200x1800` 형식도 인식합니다. 읽지 못한 항목은 관리자가 "확인 필요" 목록에서 보완해 등록합니다.
6. 맞춤 제작이므로 상품을 주문 제작 상품으로 설정하고 발송 예정일을 제작 기간에 맞게 넉넉히 잡습니다.

API 경로와 택배사 코드는 `server/smartstore/client.js` 한 곳에 모여 있습니다. 네이버 API 문서 개정으로 경로가 바뀌면 이 파일만 수정하면 됩니다. 실서버 호출은 아직 실제 계정으로 검증되지 않았으므로, 첫 연결 시 주문 한 건으로 수집 → 발주확인 → 발송처리를 순서대로 확인하세요.

### 모의(mock) 모드

API 승인 전에 흐름을 시험하려면 `SMARTSTORE_MODE=mock npm start`로 실행합니다. 관리자 스마트스토어 탭에 "모의 주문 생성" 버튼이 나타나며, 가짜 주문을 만들어 수집 · 확인 필요 보완 · 발주확인 · 발송처리 · 취소 요청까지 전체 흐름을 그대로 돌려볼 수 있습니다.

## 구조

```
server/
  index.js    HTTP 서버 · 라우팅 · 정적 파일 · 관리자 API
  orders.js   주문 생성 · 수정 · 상태 전환 · 이력 · 통계 · 역할별 응답 필터
  pricing.js  자동 견적 계산 · 규격 검증
  db.js       SQLite 스키마 · 초기 데이터
  auth.js     세션 쿠키
  password.js 비밀번호 해시 (scrypt)
  smartstore/
    client.js  네이버 커머스 API 클라이언트 (토큰 서명 · 엔드포인트 · 택배사 코드)
    mock.js    모의 클라이언트
    parse.js   구매 옵션 → 제작 규격 변환
    sync.js    수집 · 발주확인 · 발송처리 · 취소 처리 · 스케줄러
public/
  index.html · app.js · styles.css   PWA 프론트엔드 (빌드 불필요)
  manifest.webmanifest · sw.js       설치 · 오프라인 셸
  backup.js   SQLite 온라인 백업 (VACUUM INTO)
deploy/       서버 설치 스크립트 · 배포 안내
test/         node --test 기반 테스트
data/         SQLite 데이터베이스 (git 제외)
```

## 운영 시 유의사항

- `data/blackout.db` 파일을 정기적으로 백업하세요 (파일 복사만으로 복구 가능).
- 공장 계정은 하나를 공유해도 되지만, 작업자별 이력을 남기려면 계정을 따로 만드는 것이 좋습니다.
- 로그인 실패는 아이디당 10분에 10회로 제한됩니다.
