# BLACKOUT 주문관리 앱

업체(시공업체) · BLACKOUT 관리자 · 제조공장이 하나의 시스템에서 주문을 처리하는 전용 주문관리 앱입니다.
휴대폰에 설치할 수 있는 **모바일 웹앱(PWA)** 방식이며, 외부 패키지 없이 Node.js 22 내장 SQLite로 동작합니다.

이 저장소는 기획안의 **1차 범위**를 구현합니다.

| 단계 | 범위 | 상태 |
|---|---|---|
| 1차 | 업체 주문 · 자동 견적 · 관리자 화면 · 공장 주문관리 · 송장 등록 · 변경 이력 | 구현 완료 |
| 2차 | 네이버 스마트스토어 주문 자동 수집 · 발주확인 · 송장 연동 | 미구현 (아래 "2차 연동 준비" 참고) |
| 3차 | 자동 결제 · 정산 · 알림 · 고급 분석 | 미구현 |

## 실행

요구 사항: Node.js 22.5 이상 (내장 `node:sqlite` 사용). 별도 `npm install` 불필요.

```bash
npm start            # http://localhost:3000
npm run dev          # 파일 변경 시 자동 재시작
npm test             # 견적 계산 · API 권한 · 주문 흐름 테스트
```

최초 실행 시 `data/blackout.db`가 생성되고 아래 계정이 자동 등록됩니다. **운영 전 반드시 비밀번호를 변경하세요.**

| 역할 | 아이디 | 초기 비밀번호 | 비고 |
|---|---|---|---|
| 관리자 | `admin` | `admin1234` | 환경변수 `ADMIN_PASSWORD`로 변경 가능 |
| 공장 | `factory` | `factory1234` | 환경변수 `FACTORY_PASSWORD`로 변경 가능 |
| 업체(데모) | `vendor` | `vendor1234` | `SEED_DEMO=0`이면 생성하지 않음 |

환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서비스 포트 |
| `HOST` | `0.0.0.0` | 바인딩 주소 |
| `DB_PATH` | `data/blackout.db` | SQLite 파일 경로 |
| `SECURE_COOKIES` | 미설정 | HTTPS 뒤에서 운영 시 `1` (세션 쿠키 Secure 플래그) |

운영 배포 시에는 HTTPS 리버스 프록시(nginx, Caddy 등) 뒤에 두고 `SECURE_COOKIES=1`을 설정하세요. PWA 설치(홈 화면 추가)는 HTTPS에서만 동작합니다.

## 휴대폰 설치 (PWA)

1. 휴대폰 브라우저(iOS Safari / Android Chrome)로 서비스 주소에 접속합니다.
2. iOS: 공유 → "홈 화면에 추가". Android: 메뉴 → "앱 설치" 또는 "홈 화면에 추가".
3. 홈 화면 아이콘으로 실행하면 전체 화면 앱처럼 동작합니다.

## 역할별 기능

### 업체 (vendor)
- 제품 형태(편개형/양개형/프리형), 가로×세로(mm), 프레임 색상, 허니콤 원단, 수량 입력
- 입력 즉시 **자동 견적** (최소 주문면적 · 업체별 단가 · 유형별 추가금 · 택배비 자동 적용)
- 배송지 · 수령인 · 설치 요청사항 입력 후 주문
- 접수/보류 상태에서는 주문 내용 수정 · 취소 가능 (수정 시 금액 자동 재계산, 이력 기록)
- 주문 진행 상태 · 택배사 · 송장번호 조회

### 관리자 (admin)
- 전체 주문 조회 (상태 · 업체 · 검색)
- 결제 확인 후 **발주 승인** → 공장에 자동 전달 / 보류 / 취소
- 업체 관리: 업체별 납품단가, 거래 중지
- 계정 관리: 업체 · 공장 · 관리자 계정 생성, 비밀번호 재설정, 사용 중지
- 가격 설정: 기본 단가, 최소 주문면적, 택배비, 제작원가, 제작 치수 범위, 제품 형태별 추가금
- 매출 · 마진 대시보드 (기간 · 월별 · 업체별), 관리자 메모(공장 · 업체 비노출)

### 공장 (factory)
- 승인된 **제작 주문서**만 확인 (제작 규격 · 배송지 · 설치 요청)
- 제작 시작 → 제작 완료 · 송장 등록(출고) → 송장 정정
- 주문서 인쇄 (브라우저 인쇄)
- **판매가 · 단가 · 마진 · 업체명 · 업체 목록 · 관리자 메모는 API 응답 자체에서 제거**되어 노출되지 않습니다.

## 주문 진행 단계

```
주문 접수(received) ─▶ 발주 승인(approved) ─▶ 제작 중(in_production) ─▶ 출고(shipped) ─▶ 배송 완료(delivered)
      │  ▲                    │
      ▼  │                    ▼
   보류(on_hold)           취소(cancelled)
```

| 전환 | 가능 계정 |
|---|---|
| 접수 → 승인 / 보류 / 취소 | 관리자 |
| 접수 · 보류 → 취소 | 업체, 관리자 |
| 승인 → 제작 중 | 공장 |
| 제작 중 → 출고 (송장 필수) | 공장 |
| 출고 → 배송 완료 | 업체, 관리자 |
| 승인 → 보류 / 취소 (제작 전 회수) | 관리자 |

규격 · 옵션 검증은 주문 생성 시 서버에서 수행되며, 통과하지 못한 주문은 생성되지 않습니다. 모든 생성 · 수정 · 상태 변경 · 송장 변경은 `order_history`에 기록됩니다.

## 가격 계산

```
실제 면적      = 가로(mm) × 세로(mm) / 1,000,000
과금 면적      = max(실제 면적, 최소 주문면적)        # 기본 2㎡
제품금액       = 과금 면적 × 단가 × 수량            # 단가: 업체별 단가 > 기본 단가(90,000원/㎡)
유형 추가금    = 제품 형태별 추가금 × 수량
최종 주문금액  = 제품금액 + 유형 추가금 + 택배비      # 택배비 기본 8,800원 (업체 부담, 1회)
마진(관리자)   = 제품금액 + 유형 추가금 − 제작원가
```

예시: 편개형 1,000×2,000mm (2㎡) → 180,000 + 8,800 = **188,800원**

기본값은 단가 90,000원/㎡, 양개형·프리형 추가금 각 50,000원입니다. 제작원가 60,000원/㎡는 마진 계산용 예시 값이므로 관리자 "가격설정" 화면에서 실제 값으로 변경하세요. 설정 변경은 이후 주문부터 적용되고, 기존 주문 금액은 주문 시점 값으로 보존됩니다.

## API 개요

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| POST | `/api/auth/login` · `/logout` · `/password` | - | 로그인 · 로그아웃 · 비밀번호 변경 |
| GET | `/api/meta` | 전체 | 제품 형태 · 색상 · 상태 · 가격 기준 (역할별 필터링) |
| POST | `/api/quote` | 업체, 관리자 | 자동 견적 |
| GET / POST | `/api/orders` | 전체 / 업체, 관리자 | 주문 목록 · 생성 |
| GET / PATCH | `/api/orders/:id` | 전체 / 업체, 관리자 | 상세(이력 포함) · 수정 |
| POST | `/api/orders/:id/status` | 역할별 | 상태 전환 (출고 시 송장 필수) |
| POST | `/api/orders/:id/tracking` | 공장, 관리자 | 송장 정정 |
| GET / POST / PATCH | `/api/vendors` | 관리자 | 업체 관리 |
| GET / POST / PATCH | `/api/users` | 관리자 | 계정 관리 |
| GET / PUT | `/api/settings` | 관리자 | 가격 설정 · 제품 형태 |
| GET | `/api/stats` | 관리자 | 매출 · 마진 통계 |

## 2차 연동 준비 (네이버 스마트스토어)

- `orders.source` 컬럼(`vendor` / `smartstore`)과 `external_ref`(스마트스토어 주문번호)가 이미 있습니다. 관리자 화면에서 스마트스토어 주문을 수동 등록할 수 있습니다.
- 자동 연동은 네이버 커머스 API(판매자 계정의 API 이용 신청 · 애플리케이션 등록) 승인 후 `server/` 아래에 별도 모듈로 추가하면 됩니다. 수집한 주문은 `createOrder`와 같은 검증을 거쳐 `received` 상태로 들어오고, 관리자가 규격 · 취소 여부를 확인한 뒤 승인하는 흐름을 유지하는 것을 권장합니다.
- 공장이 송장을 등록하면 `status`가 `shipped`로 바뀌고 `order_history`에 기록되므로, 이 시점을 스마트스토어 발송 처리 API 호출 지점으로 쓸 수 있습니다.

## 구조

```
server/
  index.js    HTTP 서버 · 라우팅 · 정적 파일 · 관리자 API
  orders.js   주문 생성 · 수정 · 상태 전환 · 이력 · 통계 · 역할별 응답 필터
  pricing.js  자동 견적 계산 · 규격 검증
  db.js       SQLite 스키마 · 초기 데이터
  auth.js     세션 쿠키
  password.js 비밀번호 해시 (scrypt)
public/
  index.html · app.js · styles.css   PWA 프론트엔드 (빌드 불필요)
  manifest.webmanifest · sw.js       설치 · 오프라인 셸
test/         node --test 기반 테스트
data/         SQLite 데이터베이스 (git 제외)
```

## 운영 시 유의사항

- `data/blackout.db` 파일을 정기적으로 백업하세요 (파일 복사만으로 복구 가능).
- 공장 계정은 하나를 공유해도 되지만, 작업자별 이력을 남기려면 계정을 따로 만드는 것이 좋습니다.
- 로그인 실패는 아이디당 10분에 10회로 제한됩니다.
